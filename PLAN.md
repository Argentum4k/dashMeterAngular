# План реализации приложения для подсчета БЖУ

## Архитектура приложения

Приложение будет состоять из следующих компонентов:

- **Главная страница** (`/`) - интерфейс ввода БЖУ и отображение сегодняшних приемов пищи
- **Страница настроек** (`/settings`) - ввод/изменение целевых значений БЖУ
- **Страница истории** (`/history`) - просмотр истории по дням и графики

## Структура данных

### Модели данных:

- `Targets`: `{ proteins: number, fats: number, carbs: number }` - целевые значения в порциях
- `Meal`: `{ id: string, time: string, proteins: number, fats: number, carbs: number }` - один прием пищи (id - уникальный идентификатор)
- `DailyData`: `{ date: string, meals: Meal[] }` - данные за день

### localStorage:

- `bju_targets` - целевые значения БЖУ
- `bju_meals` - объект `{ [date: string]: Meal[] }` где ключ - дата в формате YYYY-MM-DD

## Компоненты и сервисы

### 1. Сервис хранения данных (`src/app/services/storage.service.ts`)

- Методы для работы с localStorage
- `getTargets()`, `saveTargets()`, `getMeals(date)`, `saveMeal()`, `updateMeal(date, mealId, meal)`, `deleteMeal(date, mealId)`, `getAllMeals()`
- Автоматическое сохранение при изменениях
- Генерация уникальных ID для приемов пищи

### 2. Компонент настроек (`src/app/components/settings/settings.component.ts`)

- Форма ввода целевых значений БЖУ (шаг 0.5)
- Валидация (значения >= 0)
- Сохранение в localStorage
- Редирект на главную после сохранения

### 3. Главный компонент (`src/app/components/home/home.component.ts`)

- Отображение таблицы "норма" vs "съедено за день" для БЖУ
- Три блока с кнопками +/-0.5 для белков, жиров, углеводов
- Кнопка "добавить прием пищи" / "сохранить изменения" (динамически меняется при редактировании)
- Список приемов пищи за сегодня (время и БЖУ) с кнопкой редактирования ✏️
- Состояние редактирования: `editingMealId: string | null`
- При клике на ✏️ - загрузка значений приема в счетчики и переход в режим редактирования
- При сохранении в режиме редактирования - обновление существующего приема
- Ссылка на настройки внизу страницы
- Автоматический расчет "съедено за день" из приемов пищи

### 4. Компонент истории (`src/app/components/history/history.component.ts`)

- Список дней с общей статистикой
- Графики потребления БЖУ по дням (Chart.js)
- Возможность просмотра деталей по каждому дню

### 5. Обновление роутинга (`src/app/app.routes.ts`)

- `/` - главная страница
- `/settings` - настройки
- `/history` - история

### 6. Глобальные стили (`src/styles.scss`)

- Темная тема (цветовая схема)
- Mobile-first подход
- Базовые стили для кнопок, форм, таблиц

## Детали реализации

### Интерфейс главной страницы (по картинке):

- Верхняя часть: таблица с колонками "норма" и "съедено за день" для БЖУ
- Средняя часть: три блока (белки, жиры, углеводы) с кнопками +/-0.5 и текущим значением
- Кнопка "добавить прием пищи" / "сохранить изменения" - сохраняет текущие значения и сбрасывает счетчики (текст меняется в режиме редактирования)
- Нижняя часть: список "предыдущие приемы" с временем и БЖУ, рядом с каждым приемом кнопка ✏️ для редактирования
- В самом низу: ссылка на настройки

### Логика работы:

1. При первом запуске (нет `bju_targets` в localStorage) - редирект на `/settings`
2. На главной странице пользователь настраивает БЖУ для текущего приема пищи кнопками +/-
3. При нажатии "добавить прием пищи" - сохраняется текущее время и значения, счетчики сбрасываются
4. При клике на ✏️ рядом с приемом:
   - Значения приема загружаются в счетчики
   - Кнопка меняется на "сохранить изменения"
   - Устанавливается режим редактирования (`editingMealId`)
5. При сохранении в режиме редактирования - обновляется существующий прием (сохраняется его ID и время), счетчики сбрасываются, режим редактирования отключается
6. "Съедено за день" автоматически пересчитывается из всех приемов за сегодня
7. Все значения хранятся в порциях с шагом 0.5

### Стилизация:

- Темная тема: темный фон, светлый текст
- Минималистичный дизайн
- Крупные кнопки для мобильных устройств
- Адаптивная верстка (mobile-first)
